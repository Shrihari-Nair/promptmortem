# Stage 6: Analysis and report (M6)

**Pairing:** per case and metric, old vs new on the same repeats only (a repeat missing on either side is dropped). Scores are oriented higher = better; pairwise preference is in [-1, 1] (+1 = new preferred, judged in both A/B orders; a disagreement is `disputed` and counts as a tie).
**Noise (`pipeline/collect.py`, `verdicts.py`):** old-vs-old variance from the first two repeats of every case (unbiased by adaptive stopping), per cluster and shrunk toward the global estimate (LLM noise is heteroscedastic). Pairwise noise = within-case variance of the preference, floored by the A/A control.
**Verdicts per case and metric:**
- *0/1 metrics and pairwise*: exact binomial test. The new arm's deviations from the old arm's majority outcome vs a binomial at the cluster's flip rate, at the Bonferroni level alpha/m (m = comparisons in the run). `p < alpha/m` -> fixed/broken; `alpha/m <= p < alpha` -> inconclusive (suggestive); else unchanged. If even a full flip could not reach alpha at this noise and repeats, a difference or instability is *inconclusive*, never "unchanged".
- *continuous metrics*: noise band (z corrected for m).
- Why not a plain 95% band: measured on the golden benchmark, rare binary flips are heavy-tailed and a normal band flagged a no-op change in about a third of runs; the exact test with confirmation repeats flags about 5% (1 of 24 runs at 5% injected noise, 0 of 10 at 15%).
- Case bucket: broken > fixed > inconclusive > unchanged. Human overrides apply on top.
**Aggregate tests per metric:** McNemar exact on case-level outcomes (0/1), sign test (pairwise), paired bootstrap CI (all); net effect = weighted mean of per-case differences with a bootstrap CI.
**Recommendation (rules, advisory):** block if a severity >= 4 case is broken, or a metric got significantly worse in aggregate (Bonferroni over metrics, CI excludes 0) on severity >= 4 cases, even if single cases are only inconclusive; caution for other regressions or a significantly negative net effect; incomplete for partial runs; inconclusive if > 30% of cases are within noise; else ok.
**Scope stamp:** tier, complete or partial, tested / dropped / planned-but-untested / added by the deep dive, reviewed and verified shares, noise bands, per-case detection thresholds ("not detectable at this many repeats" when the repeats are too few), coverage lost, skipped judge calls, warnings.
**Human actions:** `POST /reports/{id}/verdict-override` (fine / broken / improved; stored as feedback, applied on every rebuild), `POST /reports/{id}/rescore` (re-score stored outputs with the current metrics; judge calls are cached by content; the new scores replace the old ones in one transaction only if all succeed, so a cap hit leaves the report intact), `GET /reports/{id}/export?format=md|json`. `GET /runs/{id}/report` is always rebuilt, so paused/stopped runs get a (flagged partial) report.
**Golden benchmark (`app/benchmark/golden.py`, fake LLM `<!-- fake-app: {...} -->` directives):** planted regression (refund over-promising, severity 4), planted improvement (verbose answers to "explain" questions), no-op rewording, injectable noise. M6 gate tests in `tests/test_m6.py`.
**Limits:** the benchmark's behaviours are synthetic, so error rates are shown for that model of noise, not for real LLMs; per-case calls need enough repeats (5 by default for contested cases); judge noise comes from judges that share blind spots with the model under test.
