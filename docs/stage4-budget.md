# Stage 4: Cost estimate and trim (M4)

Runs only after planning (needs scenarios, prompts, ideally metrics). Never constrains planning.
**Probe (`pipeline/cost_estimator.py`):** `probe_scenarios` cases, evenly spaced over input length, run on both prompts through the same `run_target` the runner will use (so those calls are cached for the run), plus a few judge calls (pointwise and pairwise). Records mean / p10 / p90 cost per call and the share of outputs that pass the programmatic checks. The probe is reused until prompts, models or metrics change (fingerprint), or you re-probe.
**Estimate:** per scenario, `repeats x (old + new target calls) + judge calls for each applicable LLM metric` (pairwise = 2 calls per pair). low / expected / high use p10 / mean / p90 per call (`cost_high_percentile`). Programmatic metrics are free.
**Priority (`prioritizer.py`):** `w1*diff_relevance + w2*severity/5 + w3*uniqueness + w4*pinned_or_flagged + w5*disputed_potential`, ranked greedily so uniqueness is measured against higher-priority items only. `disputed_potential` is a category heuristic (ambiguous, adversarial, safety_critical) until real runs measure disagreement.
**Tiers (`trimmer.py`):** Full / Balanced / Lean = 100% / 60% / 30% of the ranking (repeats 3 / 3 / 2). **Floor rule:** pinned and severity >= 4 are always included; dropping them in a custom selection returns 409 until `confirm_drop_protected` is sent. Coverage lost is listed per category and cluster, plus clusters dropped entirely.
**Levers** (defaults as PLAN 14.8): programmatic_first (LLM judges only on outputs that pass programmatic checks), cheap_judge_easy_rubrics, adaptive_repeats, early_stopping. Savings use assumed rates from `config.py` (the response says so). Repeat allocation is modelled the way the runner behaves: a share of cases stays quiet and stops after 2 repeats (assumed 60%), every other case is *confirmed* with up to `max_repeats_adaptive` repeats. So **adaptive_repeats can cost more than fixed repeats** when many cases differ (its saving is negative) and early_stopping (same stop rule, capped at the planned repeats) is what saves money; they are one factor, not two. low / expected / high assume 90% / 60% / 0% quiet cases, so the default cap (= high) covers a run where everything is contested. Measured on the golden benchmark: actual spend was inside [expected x0.8, high] in 34 of 34 runs (about 1.05x expected for no-op changes, 1.5-1.7x when many cases regress; the deep dive is not in the estimate and asks before spending).
**API:** `POST /projects/{id}/plan/estimate` (probes if needed), `/plan/trim` (custom selection), `/plan/confirm` (tier, hard cap defaulting to the tier's high estimate, freezes the scenario ids on the plan; warns if the cap is below the expected cost), `GET /plan`, `GET /plan/ranking`.

**Provider thinking (measured on real Gemini):** Gemini 2.5 bills hidden reasoning tokens as output. Judges, the scenario generator and the critic run with thinking off (`PV_JUDGE_REASONING`, `PV_GENERATOR_REASONING`, default `disable`; a judge call went from 350 to 32 output tokens with the same verdict; 2.5 Pro cannot disable it and uses `low`). The model UNDER TEST is left as your app runs it (`PV_TARGET_REASONING=default`): on real runs target replies are about 70% of the cost, so if your app calls the model with thinking off, set `PV_TARGET_REASONING=disable` to match it (and to cut the cost). **Severity anchors** in the generator prompt keep most cases at 1-3: unanchored, Gemini rated 56% of cases severity 4+, which made them all 'protected' and the cheaper tiers pointless; the estimate now also warns when protected cases exceed 40%.

**The cheap-judge lever is real:** with it on, the runner judges *easy* rubrics (pointwise, binary, short, no pinned judge model) with a cheaper model (`PV_CHEAP_JUDGE_MODEL`, else derived from the judge's provider: Gemini flash-lite, gpt-4o-mini, Claude Haiku; `fake/cheap` in tests); the pairwise regression judge never downgrades. The price ratio comes from LiteLLM's price table when both models are known (else `cheap_judge_cost_ratio`). If no cheaper model is known the lever is shown as unavailable, is forced off, and claims no savings. The report names the metrics that were judged by the cheaper model.
