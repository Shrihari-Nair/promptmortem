# Stage 7: Promptfoo export and trace import (M7)

**Export:** `GET /projects/{id}/export/promptfoo?format=yaml|json&scope=plan|all` returns a `promptfooconfig.yaml`: both prompts (`{{var}}` syntax is shared), the scenarios as tests (`vars` = the scenario input, `metadata` = id, category, cluster, severity, tier, reviewed, tags), and per-test assertions from the metrics whose `applies_to` matches. `scope=plan` is the confirmed budget plan's scenarios (all non-rejected ones if none is confirmed). Run it with `npx promptfoo@latest eval -c promptfooconfig.yaml --no-cache`; `evaluateOptions.repeat` carries our repeats.
**Mapping** (`adapters/promptfoo_export.py`): every assertion has `metric:` = our metric name and our weight. max/min_words, max_chars, equals, starts_with and the case-insensitive regex variants become `javascript` assertions; regex_required / forbidden_regex -> `regex` / `not-regex`; contains_all / contains_none -> `contains-all` / `not-contains-any` (and `i` variants); json_valid / json_schema -> `is-json`. Aggregates: all_pass = plain assertions, any_pass = `assert-set` (threshold just above 0), mean = `assert-set` (threshold 0). LLM judges -> `llm-rubric` (graded by the judge model); the pairwise regression metric -> `select-best` across the two prompts. **Not exportable:** `language_is` (reported as a warning in the YAML header and in the JSON response). Provider ids are mapped from the LiteLLM names (`gemini/x` -> `google:x`; Promptfoo reads `GOOGLE_API_KEY` where LiteLLM reads `GEMINI_API_KEY`, and the export says so).
**Verified against the real tool** (`tests/test_m7.py`, set `PROMPTFOO_BIN=/path/to/promptfoo`, skipped otherwise): a project engineered so every check type sees passing and failing outputs, run through Promptfoo's `echo` provider (the output is the rendered prompt, so both sides judge the same strings): 1,440 (test x metric) comparisons, 0 disagreements, scenario inputs reproduced exactly (JSON text included). The exported `llm-rubric` / `select-best` assertions are schema-valid and execute (their grading needs a real grader model). Python-only regex syntax (inline flags, `(?P<n>)`) is passed through as written and may not mean the same in JavaScript.
**Traces:** `POST /projects/{id}/traces/import` (generic JSONL: `input`, optional `output`, optional `expected`; same as the dataset import without a column mapper). Duplicate inputs are skipped and reported. A trace is a real input but NOT ground truth: without an `expected` value it becomes a synthetic, unreviewed scenario (it still seeds generation and is never deduplicated away); with `expected` it is verified. Traces labelled `pass`/`fail` with an observed `output` calibrate the LLM judges.
