# Stage 2: Scenario planning and review (M2)

**Flow (`pipeline/planner.py`):** dataset items become verified, pre-approved scenarios (once) -> generator per category (multilingual / safety_critical only when the description or risks mention them) plus one `diff_targeted` batch per change -> programmatic near-duplicate removal (cosine >= `dedupe_cosine_threshold`) -> critic rounds (<= `max_critic_rounds`): removes semantic duplicates and unrealistic cases, flags uncertain ones, gaps are generated and fed back -> diff relevance (0.7 generator + 0.3 embedding similarity to changed text) -> clustering per category (deterministic average linkage, ~`cluster_target_size` per cluster) -> coverage map stored on the plan. Planning is never cost-capped.
**Review queue (`GET /projects/{id}/scenarios?review_queue=true`):** cluster representatives (nearest the centroid, <= `review_queue_max_per_cluster`), critic-flagged, and the highest-diff-relevance case per cluster. Unreviewed scenarios still run later and are reported as `reviewed=false`.
**Human actions:** approve / edit / reject / pin / comment (`PATCH /scenarios/{id}`), add own scenario, generate more in a category, reject a whole cluster (`POST /clusters/{id}/reject`): proposed scenarios in it are rejected, approved/pinned/edited survive, the comment is stored and the category is regenerated.
**Feedback loop:** every action is a `feedback` row. `pipeline/feedback.py` renders them (cluster-relevant first, then recent, with the rejected examples) into the generator prompt's "constraints learned from the reviewer"; regeneration also dedupes against rejected scenarios.
**Embeddings:** sentence-transformers if installed (`uv sync --extra embeddings`), otherwise a hashed char-n-gram fallback (a warning is logged).

**Regression guards from real behaviour:** `regression_guard` scenarios are generated AFTER the other categories, from an old-prompt probe: the OLD prompt is run on `regression_probe_n` realistic inputs (dataset and trace inputs first, then generated happy-path and edge cases) and the generator is shown its actual replies, so the guards exercise behaviours the old prompt really has. Extending that category later probes again. **Feedback also includes your verdict overrides** from the report ("the case X is actually fine: ...").
